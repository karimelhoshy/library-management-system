# Decisions

One line each: what we chose and why.

- **Next.js 16.4 with Cache Components off.** Almost every page depends on the signed-in user, so plain dynamic rendering is simpler and just as fast; `cacheComponents` and `partialPrefetching` are disabled.
- **`experimental.authInterrupts` on.** Lets pages call `forbidden()` and render a real 403 page.
- **Postgres driver: `pg` (node-postgres) + Drizzle 0.45.** Works the same against Neon, Docker and any self-hosted Postgres; pool attached to Vercel Fluid via `attachDatabasePool`.
- **Correlated subqueries use raw aliases.** Drizzle drops table names in single-table selects, so subqueries use `loans l … where l.book_id = "books"."id"` to stay unambiguous.
- **Auth.js v5 with JWT sessions.** The credentials-style demo provider requires JWT; the role is re-read from the database on every request, so role changes apply at once.
- **Demo sign-in only accepts the four fixed demo ids** (`demo-ada`, `demo-leo`, `demo-maya`, `demo-sam`) and only when `DEMO_MODE=true`.
- **Availability = total − open loans − ready holds.** A "ready" hold sets a copy aside for one member, so it can't be borrowed by anyone else.
- **Every borrow/return/hold locks the book row (`SELECT … FOR UPDATE`).** Serialises changes per title so the last copy can't be double-booked; a partial unique index is the backstop.
- **One open loan and one active hold per member per title** (partial unique indexes).
- **Renewal of an overdue loan gives 14 days from today**, not from the old due date.
- **Members can borrow while overdue.** Fines and blocks are non-goals; the overdue badge and emails nudge instead.
- **Undo window is 2 minutes.** Undo borrow deletes the loan; undo return reopens it only if the copy hasn't gone to someone waiting.
- **Books table has an extra `summary` column** (one-line hook for cards) and `embedding_hash` (re-embed only when the text changes).
- **In-app hold notices are derived from hold status** (no separate notifications table).
- **Email outbox has `dedupe_key`** so the daily job never sends the same reminder twice; overdue reminders repeat weekly.
- **`ai_usage` table** backs the per-user AI rate limit (works across serverless instances, unlike memory).
- **Dates display in UTC** so server and client render identical text (no hydration mismatches).
- **Chat model `gemini-3.8-flash`, embeddings `gemini-embedding-001` @ 768 dims, normalised.** Current free-tier models per Google's docs (Nov 2026); both overridable via env.
- **Covers use plain `<img>` with a coloured fallback**, not `next/image`, to avoid image-optimisation quotas and handle missing covers cleanly.
- **Seed is deterministic** (seeded PRNG + hashed UUIDs), so `pnpm db:seed` is idempotent and every machine gets the same history.
- **Seed swap:** *Murder in the Crooked House* has no cover on Open Library, so *The Moai Island Puzzle* (another translated Japanese locked-room mystery) stands in.
- **Local dev DB: Docker `pgvector/pgvector:pg17` on port 54329** (`docker compose up -d`).
- **pnpm 12 + Node 24.** `pnpm-workspace.yaml` allow-lists build scripts (only esbuild needs one).
- **Loading skeletons only on catalog, book and loans routes.** A route-wide `loading.tsx` streams a 200 before `forbidden()` can run; staff pages render fully on the server so they return a true 403.
- **Demo staff are scoped to demo accounts.** In the public demo anyone can be Ada/Leo, so user lists, the loans desk, activity and outbox hide real (Google) accounts, and role changes/lending to them are refused.
- **AI quota check-and-record runs under a per-user advisory lock** (`pg_advisory_xact_lock`) so parallel requests can't exceed the limit.
- **Dashboard chart is a single series (loans per day)** with a hover tooltip and a screen-reader table; no legend needed for one series.
- **Chat streams newline-delimited JSON** (`text`, `status`, `books`, `proposal`, `done`, `error` events) from a route handler; no extra SDK needed on the client.
- **Write tools return proposals, stored on the assistant message.** Confirming calls the same services as the UI (`placeHold`, `borrowBook`, `renewLoan`), so every rule and permission applies; resolving twice is a no-op.
- **A reply's row is created before the model starts, and each proposal is saved the moment it's made**, so a card can be confirmed while the reply is still streaming. Later writes touch only their own part of the JSON (`||` for the text, an in-place swap for one proposal), so the finished reply never overwrites a confirmation.
- **Mini book cards = books the agent looked up that its reply names** (plus any with a proposal), capped at 4.
- **Model history replays text only**; earlier proposals are summarised inline (e.g. "[Offered to place hold "Circe": confirmed]").
- **Gemini thinking level LOW for chat** to keep replies fast; falls back to the model default if a model rejects it.
- **Cron runs at 06:00 UTC daily** (Hobby plan allows one run per day) and compares the bearer token in constant time.
- **`vercel.json` (not `vercel.ts`) for the cron** to avoid an extra dependency for one setting.
- **Email previews render in a sandboxed `<iframe srcdoc>`** so stored HTML can't run scripts.
- **Layer boundaries are lint rules, not just convention** (`@typescript-eslint/no-restricted-imports`), so the structure holds once outside contributors arrive.
- **Chat stream types live in `src/lib`** because the server writes them and the browser reads them; neither side should own them.
- **The walkthrough video records Chrome's screencast frames and encodes them with ffmpeg**, because Playwright's built-in video uses a fixed low bitrate that blurs text.
- **The voiceover uses Gemini text-to-speech (`gemini-3.8-flash-tts`), generated before recording**, so each step waits for its line to finish and the voice stays in sync without editing. macOS `say` was tried first and dropped: free, but robotic. Clips are cached by text and voice, so re-runs only pay for changed lines. `speak()` in `voice.mts` is the one place to swap providers.
- **Gemini calls fall back across models** (3.8 → 3.7 → 3.6 Flash by default, `GEMINI_MODEL` takes a comma-separated list). Free-tier models are sometimes overloaded or silent and each has its own daily quota; a model that errors with 429/5xx or hasn't started answering in 20 s is skipped, and a chat turn stays on the model that answered because thought signatures don't transfer.
- **One shared daily AI budget on top of per-user hourly limits** (`AI_DAILY_BUDGET`, default 300), checked under one advisory lock and shown on the librarian dashboard. A public demo can't drain the quota; past the budget the AI surfaces say so and the rest of the app carries on.
